<objective>
Tier 2 audit: certify the dataset and pipeline are leak-free. Three sub-audits in one script:

(a) **Per-feature classification** — walk every assignment to `result["<col>"]` in `src/features/engineering.py`, regex-scan for known leakage signatures (`shift(-N)`, `center=True`, `bfill`, `backfill`), and produce a Safe / Suspicious / Leaking verdict with line-number evidence.

(b) **Walk-forward embargo verification** — load `data/processed/train.parquet` and `data/processed/test.parquet`, intersect their pair_id sets. Any pair appearing in BOTH means its features in train rows directly informed its target in test rows — that's leakage. Per RESEARCH.md, this is the **single highest-yield finding** (the codebase splits 80/20 by row index, not by pair lifecycle).

(c) **Quality-filter rule-by-rule audit** — for each rule in `src/matching/quality_filter.py`, classify whether the rule uses post-resolution metadata (settlement outcome, settled_at, final_outcome). Rule `stale_ticker` calls `_current_year()` at runtime which is technically retroactive — flag it.

Purpose: Subtle leakage destroys backtest credibility. Phase 8 already verified determinism, but never produced a per-feature classification table. This audit produces that table and explicitly tests the embargo.

Output: `experiments/audit/audit_leakage.py` + passing fixture tests + `leakage_audit.json` containing per-feature classification, embargo report, quality-filter rule classification, and assumption stack.

Implements requirement: AUDIT-02.
</objective>
